# Mira 会话日志导出通用方法

核对日期：2026-10-29。以下 Mira 参数已由本机 0.0.697 的官方 CLI 帮助确认；Kimi 参数由本机 `kimi export --help` 确认。未读取或导出任何现有用户会话来编写本文。

## 1. 先确定要导出的内容

| 需要的内容 | 推荐方式 | 范围 |
| --- | --- | --- |
| Mira 中某个会话的历史轮次 | `ui-cli history --session KEY` | 当前 host 返回的已落定轮次，跨 agent 通用 |
| Kimi Code 原生会话归档 | `kimi export SESSION_ID --output PATH` | Kimi 原生 ZIP；具体包含项以该版本的导出实现为准 |
| 程序报错、启动故障 | `ui-cli diag` 或 `.mirasim/logs/server.log` | 服务诊断，不是对话记录 |

不要把 `history` 当成所有 agent 底层原始事件的完整备份。运行中未落定的输出可能不在其中，工具细节、附件和思考过程是否保存取决于 agent 与 Mira 的实际记录。需要可恢复的原生归档时，应再使用对应 agent 的原生导出功能。

## 2. 找到当前 Mira 官方命令

Windows PowerShell：

```powershell
$M = Join-Path $env:USERPROFILE '.mirasim\bin\mirasim.cmd'
Test-Path $M
& $M version
& $M ui-cli help sessions
& $M ui-cli help history
```

macOS / Linux：

```bash
M="$HOME/.mirasim/bin/mirasim"
"$M" version
"$M" ui-cli help sessions
"$M" ui-cli help history
```

如果设置了 MIRASIM_HOME，按该目录查找 bin 下的官方启动器。若文件不存在，先打开 Mira；仍找不到时检查 `Get-Command mirasim` / `command -v mirasim`，不要硬编码某一版本 server.cjs 路径。桌面更新可能搬动实际程序，而官方启动器会指向当前安装。

本机桌面常用端口是 4970，headless 常用 4939，但自定义实例可能不同。应使用目标实例的端口，不能把不带端口时可能启动的一次性私有 host 当成当前桌面。

## 3. 定位会话

```powershell
# 列出最近 50 条会话记录；只看元数据，不是导出正文。
& $M ui-cli --port 4970 sessions --limit 50

# 按标题等关键字搜索，并显示完整行字段。
& $M ui-cli --port 4970 sessions --query '部分会话标题' --full

# 或限定工作区。
& $M ui-cli --port 4970 sessions --cwd 'C:\path\to\workspace' --full
```

从结果中取目标会话的标识，原样作为下面的 KEY。不要使用显示标题代替标识，也不要把不同系统的会话 ID 混用。没有结果时先核对实例端口、工作区、会话来源及是否归档；不要立即新建或删除会话。

## 4. 导出 Mira 会话历史（推荐助手脚本）

本项目提供 `session-log-export/export_session.py`。需要 Python 3.9+，只用标准库。它调用官方 CLI，不直接扫描会话目录或读取凭据；保留完整 JSON 返回结构，使用 UTF-8 写入，不覆盖现有文件。

在本项目根目录运行：

```powershell
python .\session-log-export\export_session.py --port 4970 list --query '部分会话标题'

python .\session-log-export\export_session.py --port 4970 export --session '这里替换为会话KEY' --output '.\session-history.json'
```

只需要最近 20 个已落定轮次时：

```powershell
python .\session-log-export\export_session.py --port 4970 export --session '这里替换为会话KEY' --limit 20 --output '.\session-history-last20.json'
```

没有 `--limit` 时不主动截取最新 N 条；最终导出范围仍以当前官方 host 实际返回的数据为准。文件中的 `history` 字段是原始返回对象，其他字段只记录导出时间、端口及选择的会话标识。

命令路径自定义时使用 `--mira`，全局选项放在 list/export 前：

```powershell
python .\session-log-export\export_session.py --mira 'D:\path\mirasim.cmd' --port 4970 export --session '会话KEY' --output '.\session-history.json'
```

macOS/Linux 的 Python 脚本参数相同，路径使用本机路径即可。Windows batch 启动器不接受本脚本禁止的 shell 控制字符；遇到这类标识会明确报错，不会替用户拼接并执行危险 shell 文本。

### 不使用助手脚本

官方核心命令只有这一条，可在你自己的终端直接查看：

```powershell
& $M ui-cli --port 4970 history --session '会话KEY'
```

需要保存时推荐前面的 Python 脚本，以避免 Windows PowerShell 5.1 默认重定向编码导致中文乱码，也避免命令失败时得到一个被误认为成功的空文件。

## 5. Kimi Code 原生会话 ZIP

先核对当前版本的帮助和可执行位置：

```powershell
Get-Command kimi
kimi export --help
```

导出明确指定的 Kimi 原生 session ID：

```powershell
kimi export 'Kimi原生SESSION_ID' --output '.\kimi-session.zip' --no-include-global-log
```

`--no-include-global-log` 是当前版本支持的参数：避免默认把全局 `kimi-code.log` 一并打进会话归档。如果你的版本帮助里没有该参数，就按那个版本的帮助操作，导出后自行检查 ZIP 内容。本文不假设所有版本都支持同样选项。

不知道原生 ID 时，可以先在**目标工作目录**执行 `kimi export --output ... --no-include-global-log`，保留其上一会话确认提示，核对选中的会话后再继续；不要默认加 `--yes`。Mira 的会话 KEY 不一定等于 Kimi 原生 ID，不能直接互换。若应用为该 agent 设置了独立 KIMI_CODE_HOME，应使用实际对应的数据目录，否则默认 CLI 可能看不到目标会话。

## 6. 导出后检查

1. 确认命令成功、文件存在且非空，并能作为 JSON/ZIP 正常打开。
2. 核对首尾轮次是否符合预期；运行中会话先等待当前轮次结束再导出。
3. 确认不是空的 `history` 或被 `--limit` 截取而误认为完整备份。
4. 会话内容可能有用户输入、工具输出、路径或粘贴的秘密。会话导出没有通用自动脱敏保证，分享前自行检查；不要整包上传 `.mirasim` 或 `.kimi-code`，其中另有账号配置和凭据。

如果会话来自远程机器，CLI 连接的 host 及原生记录所在机器必须一致。`diag` 诊断包落在 host 磁盘；本文助手的 JSON 则写到运行该 Python 脚本的机器，两者不能混淆。

## 7. 验证边界

本轮已核对官方帮助，助手脚本通过 UTF-8 中文数据保留、禁止覆盖、CLI 错误处理与 Windows 参数保护测试。测试使用合成数据，没有读取你的现有会话。真实目标会话的内容完整性需要在你选择并导出后，按第 6 节检查。
