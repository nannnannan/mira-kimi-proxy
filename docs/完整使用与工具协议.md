## 2. 接入顺序与字段约定

1. 第一次请求：`messages` 中放入 system 提示和用户问题，`tools` 填入第 5 节工具数组。
2. 模型返回 `assistant.tool_calls` 后，保留完整 assistant 消息，包括 `reasoning_content`。
3. 用 `json.loads(call["function"]["arguments"])` 解析参数，按工具名分派给你自己的执行函数。
4. 追加 `role: "tool"` 消息，用 `tool_call_id` 精确对应调用的 `id`，`content` 填工具结果字符串。
5. 带完整消息历史与相同工具定义再次请求，直到模型给出最终回答或发出新的工具调用。

`tools[].function.parameters` 是参数 schema；`tool_calls[].function.arguments` 是序列化后的 JSON 字符串，二者不可混淆。`Read` 的路径参数名是 `path`，不是 `file_path`。一次出现多个工具调用时，每个调用都要有独立 id 和对应结果；不要合并成一条结果。

没有执行后端的工具请从 tools 中删除，并同步调整系统提示中不适用的能力描述。工具定义本身不提供读文件、执行命令、MCP、子代理或定时任务实现。

## 7. SSE 流式格式

- 逐行读取 `data:` 数据，以空行划分 SSE 事件。
- `choices[].delta.content` 为正文增量，`reasoning_content` 为推理内容增量；分开累加。
- `choices[].delta.tool_calls[]` 中，使用 choice index 与 tool-call index 定位对应调用。
- 同一调用的 function.name 和 function.arguments 可能分段到达，依序拼接；等完整后再解析 arguments。
- id 可能只在首段出现，要保留；不要把不同 index 的参数混合。
- `finish_reason: "tool_calls"` 表示需要工具执行；`finish_reason: "stop"` 表示该轮结束。
- usage 可能在 `choices: []` 的单独 chunk 中，不应丢弃。
- `data: [DONE]` 表示流结束。网络中断且没有完整结束标记时，不要把不完整参数拿去执行。

## 8. 从本单文档构造请求的 Python 示例

下面代码直接读取本文内嵌的提示和工具数组，因此不依赖额外的 `tools.json` 或 `adapter.py`。示例只构造请求，不执行工具，也不自动发出计费请求。实际请求时使用第 1 节地址和本地密钥。

    fragment = text.split("<!-- BEGIN " + name + " -->", 1)[1]

    assert lines[0].startswith("````") and lines[-1].startswith("````")
